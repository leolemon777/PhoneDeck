## 1. 阅读规则与决策效力

本文可单独交给评审模型阅读。需要核实实现时，再读取第 3 节列出的源码与交接证据。

- **事实**：本地源码可见，或已有交接记录；必须说明是哪一种证据。
- **要求**：目标发布必须满足的行为；不表示代码已经做到。
- **建议数值**：本规格提出的容量、时间和性能门槛，须在 M0 用基准测试评审冻结，不能发布前临时降低。需求行内嵌的具体数值（如 6 秒看门狗、15 秒恢复窗、组合键上限等）均为提案值，一律以 D03/D04 冻结结果为准；冻结时对全文行内数值做全局替换并复核引用，避免行内数值与冻结值脱钩。
- **待决策**：有明确负责人角色、截止阶段和未决定时的退路，见第 22 节。
- “必须/不得”约束本文获批准后的对应范围；草案本身不授权一次性实现全部功能。
- 新增契约字段、配对机制及状态机均为目标设计，除明确标注“当前”者外，不得直接写成现有 protocol v2 的事实。
- 当前行为冲突按“已确认的最新用户决策 → 对应源码 → 有日期和版本的实测记录 → 旧说明”核对。新行为建议不能覆盖已有用户选择。

当前已确认方向：Android/iOS 手机搭配 Windows/macOS 电脑；动态多电脑；多输入法；点击/按住与共享麦克风；简洁浅深主题；配置集中手机、桌面轻量化。最低系统、具体实现库、性能预算、渠道与阶段日期仍需要评审。

评审结论须区分：可以公开源码、可以发布技术预览、可以声明指定组合稳定、可以声明四端完整支持。这四种结论不可互换。

## 2. 产品目标与范围

### 2.1 用户最终要获得什么

把一台闲置手机变成可长期使用的麦克风与快捷操作面板；在可互访的本地网络内选择电脑，可靠地发送受控按键、文字或语音。识别由用户自行安装的桌面语音软件完成，PhoneDeck 不自建云端识别服务。

完整体验：下载正确安装包 → 安装并完成权限/驱动引导 → 扫码配对 → 测试按键/供音 → 选择工作模式 → 日常使用 → 故障自助定位 → 安全更新且保留配置。

### 2.2 范围分层

| 范围 | 包含 | 边界 |
|---|---|---|
| 核心 | 单目标按键/文本、点击/按住听写、共享麦克风、设备管理、配置与更新 | 主路径必须能自助安装与恢复 |
| 完整兼容目标 | Android/iOS × Windows/macOS，1 手机到 5 电脑，混合系统，分级输入法适配 | 只对支持矩阵内具体组合承诺 |
| 兼容保留 | Android USB/ADB、现有受控宏、旧固定动作、Windows 蓝牙按键 | 降级行为必须明确，不能绕过身份校验 |
| 条件扩展 | Windows ARM64、Mac Intel、更多键盘布局、蓝牙耳机、10 台压力测试 | 未通过专项认证就标实验或不支持 |
| 暂缓 | Linux 接收端、云中继、账户云同步、自研虚拟声卡、插件市场、任意脚本、复杂自动化 | 不作为本轮稳定发布前置；任意远程 shell 明确禁止 |

“全兼容”定义为：覆盖声明支持的组合，并对不支持和无法检测的情况给出真实反馈。不得用“所有输入法”“所有手机”“无限电脑”等无法验收的宣传。

### 2.3 发布档位

| 档位 | 可公开声称 | 必须完成 | 不必等待 |
|---|---|---|---|
| R0 源码/技术预览 | 源码开放；明确版本的实验功能可试用 | 许可证与资产检查、秘密扫描、可构建说明、真实状态、预览安装/恢复说明、已知问题 | iOS、五机稳定、所有引擎认证 |
| R1 Android + Windows 稳定 | 支持矩阵内 Android→Windows 自助可用 | 无 USB 首配、长期签名、干净安装、两台 Windows 路由/共享、生命周期与更新验收 | Mac 稳定、iOS |
| R2 Android + Windows/Mac 稳定 | Android 管理混合电脑；实测范围内 5 台 | Mac 正式分发/权限/设置能力、混合五机、引擎认证和长测 | iOS 完整客户端 |
| R3 四端完整稳定 | Android/iOS × Windows/macOS | 四种组合、iOS 生命周期/分发/更新、两类手机各自五机、全套发布门 | 暂缓能力 |

R0 也不能带已知的未授权输入、秘密泄漏或丢配置问题公开分发。未完成的平台不阻断较早档位，但下载页、按钮与宣传必须限定范围。档位是本文的发布范围标签，不替换原 M0–M5 和 B01–B06 编号，也不决定营销版本号。

## 4. 兼容矩阵与认证规则

### 4.1 支持等级

每条记录使用“正式支持 / 预览 / 实验 / 待验证 / 不适用”。正式支持必须绑定 OS 精确版本、CPU、客户端/接收端版本、输入法版本、驱动版本、传输和模式。测试没做写 NOT_RUN，设备不可用写 BLOCKED；均不是 PASS。

| 轴 | 基础认证范围提案 | 扩展与拒绝策略 |
|---|---|---|
| Android | 至少 3 厂商、4 台真机；包含系统下限附近、已有 Samsung、近期系统；至少 1 台低内存旧机 | API 26 是当前构建下限，不是所有版本已认证；无 Google 服务设备如声明支持须独立测试 |
| iOS | 至少 2 代 iPhone；最终最低系统与发布时最新稳定系统 | iOS 17+ 仅原型候选；iPad、蓝牙耳机不自动继承认证 |
| Windows | Windows 11 x64，至少 2 台真实设备；普通用户、非中文用户名也测 | Windows 10/ARM64/Server 独立决策；禁止凭模拟或 x64 构建推断原生 ARM 支持 |
| macOS | Apple Silicon，候选下限 14.2 与发布时最新稳定版分别测 | Intel 先编译、再真机；达不到就不提供“稳定 Intel”标签 |
| 输入目标软件 | 系统文本框、浏览器、编辑器、终端、至少一种 Agent 工具；中英 IME、前台焦点变化 | 管理员窗口、锁屏/登录、安全输入、游戏反作弊分别列限制，不绕过系统保护 |
| 键盘与文本 | 逻辑 PRIMARY、真实 CTRL/CMD/OPTION、ANSI 常用键、中英 Unicode/emoji | JIS/ISO、AltGr/死键及其他语言布局单列认证；不得按字符猜物理键 |
| 网络 | IPv4 家庭局域网、有线 PC+无线手机、热点、多网卡、广播禁用恢复 | IPv6-only 必须实现并验证或明确暂不支持；VPN/访客隔离不能承诺必然互通 |
| 音频路由 | 手机内置麦克风，Windows VB-CABLE，Mac BlackHole/经验证聚合设备 | USB/蓝牙耳机、其他虚拟设备、独占占用与采样率变化专项验证 |

系统“最新”在每次候选冻结时填入准确版本号，不能作为永久的矩阵值。

### 4.2 四种基础组合

Android→Windows、Android→Mac、iOS→Windows、iOS→Mac 分别覆盖：首次安装/配对、按键/文本、managed 点击/按住、shared、停止/取消、生命周期、升级。

每类手机分别测试 Windows+Mac 混合组。核心四组合不得用组合抽样省略；引擎×主题×布局的非核心笛卡尔积可采用风险驱动的两两组合覆盖，但必须记录未测组合与理由。

## 5. 需求标识与追踪约定

第 6–15 节的每一行是一个需求组。优先级 P0=对应档位的阻断项，P1=该档位完整体验项，P2=可单独延期；P1 若被列入对外承诺，也必须验证。`起始门`表示首次强制执行的发布档位，之后继承；范围外平台可 N/A，但需要审批和理由，N/A 由对应档位放行决定的负责人（用户/维护者，见第 20.2 节第 7 条）批准，实现者不得自行标记，并按第 19.2 节记录批准角色。

每个需求组必须映射第 18 节的一项或多项测试；测试步骤中的枚举变体需要分别执行，不能做一个样例就勾选整组。后续实施允许细分编号，不得重用已删除编号。

| INS-04 | P1/R1 | 首次运行说明权限用途，可拒绝后重试；无音频驱动仍可用按键，无输入权限仍可共享供音 | V03、V07 |

新用户主流程：安装 → 选择电脑名 → 最小权限/驱动诊断 → 开启配对窗口 → 手机扫码、两端确认 → 测试按键 → 测试音频 → 用户主动开始工作。向导可稍后继续；“跳过语音”不妨碍按键使用。

桌面继续轻量化。配对确认、撤销手机和系统权限说明是必要的本机信任操作，可用按需窗口；不得因此恢复大而全的常驻桌面配置中心。主题、布局和普通设置仍以手机为入口。

当前协议骨架保留 `protocolVersion/requestId/sessionId/targetComputerId`；目前 LAN header 为 `X-PhoneDeck-Token`。目标逐手机认证、generation/lease 与授权范围须新增能力或协议版本后协商，不在旧 v2 下偷偷改变必填字段。

旧固定动作 compatibility 不能让缺失 target 或 protocolVersion 的 LAN 请求绕过新会话授权。需盘点旧动作中可触发语音的路径：保留语义，不保留未授权副作用。兼容窗口按渠道和客户端版本记录。

错误分为未授权、错误目标、能力不支持、忙碌、配置冲突、过期会话、输入权限不足、音频设备缺失、探针未知、超时。HTTP 与产品错误码一一记录；未知错误不自动重试有副作用操作。请求格式/大小错误在进入输入或音频状态机前拒绝。

现有受控动作基线：组合最多 4 键，holdMs 20–500 ms，文字最多 4096（必须明确跨语言长度单位），宏 1–8 步、单步延迟 0–2000 ms。这不包含引擎 hold 会话时长；hold 会话必须另有租约与最大持续预算。总执行时长、宏取消及队列积压上限在 D03 冻结，不能沿用历史“20 步宏”扩大范围。

Windows SendInput 受 UIPI 限制，系统不会保证明确返回“被 UIPI 阻止”。产品应给权限差异排查提示，不能声称能精确识别所有阻断，更不能默认提升到管理员运行。[微软 SendInput 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

## 9. 语音模式、状态与生命周期

### 9.1 三层真实状态

分别表示手机采音、接收端供音、输入法采集/转写。`audio.streaming=true` 不等于输入法在识别；探针 unknown 不当成 stopped；转写成功只能由测试文本/用户观察确认，不能由发出快捷键推断。

目标状态机：IDLE → STARTING → ACTIVE → STOPPING → IDLE；失败进入 ERROR 并清理资源。停止等待期间立即停止本地采音，但可继续传送已采集尾帧。STOPPING 期间不得启动新会话抢占旧尾音。共享显示逐目标供音状态。

## 16. 契约冻结与架构实施边界

### 16.1 先固定行为，再提取公共核心

继续 Android Java、Windows .NET 原生后端、Mac 现有 .NET 后端；iOS 候选 Swift 原生音频与界面。共享的是契约、测试向量、身份/会话语义和配置 schema，不要求四端使用同一 UI 框架。大型 Activity/Program 可随任务逐步拆分，不能把整体重写作为发布前提。

建议新增 `contracts/`（尚未创建），保存 JSON schema、合法/非法请求、错误映射、能力组合、状态转移和配置迁移夹具；Java/C#/后续 Swift 消费同一批样例。Windows/Mac 先通过等价行为测试，再按收益提取 Receiver.Core；平台输入、实时音频与权限始终独立。

### 16.2 M0 必须交付的契约表

| 契约 | 必须冻结的内容 |
|---|---|
| 发现与配对 | 服务名/端口、二维码版本/大小、证书绑定、一次性材料长度/有效期、错误/限速、手工替代方案 |
| 身份与授权 | computerId/clientId/pairingId、凭据作用域、存储、轮换、撤销、旧共享令牌迁移 |
| 请求确认 | requestId作用域、规范化载荷哈希、去重TTL与容量、并发互斥、ACK含义、响应丢失后的查询/重试策略 |
| 会话 | sessionId、所有者、代次、租约、启动/停止/取消顺序、终止墓碑、重连窗口、未知状态与过期处理 |
| 能力 | supported/available/busy/permissionDenied 分开；协商失败的降级；每端最低版本与旧协议窗口 |
| 音频 | 字节序、PCM格式、帧长、实际采样率转换、目标header、EOF、队列/尾音上限与流冲突 |
| 配置 | schema/revision、分组写入、热应用互斥、原子保存、迁移/备份/导出秘密隔离 |
| 错误与诊断 | 稳定错误码、HTTP映射、可重试性、中文/英文提示、脱敏字段、时钟与快照新鲜度 |

候选参数：输入请求仅允许短时网络重试，去重缓存至少覆盖最长重试预算并按 clientId 分区；对过期输入不得再次执行。缓存耗尽必须拒绝或限流，不能通过驱逐近期请求制造重复执行。具体数值由 D03 冻结，安全评审前不自创密码协议。

Exactly-once 跨进程崩溃不能仅靠内存 requestId 保证：接收端重启后不自动补发可能已执行的输入，明确显示结果未知；需要时引入持久化记录，但不能因此记录敏感正文。按键已执行但 ACK 丢失的用例必须独立验证。

### 16.3 会话竞态必须明确的规则

1. start 与 stop 同时到达：stop 获得本代次终止语义；已取消 session 不再被迟到 start 建立。
2. 旧 stop 晚到：只能清理对应旧 session，不能停止新 session。
3. 新连接替换旧 socket：先验证所有者和代次，不以“最新连接”自动夺权。
4. 启动部分成功：音频/引擎任一失败清理本会话；引擎仍可能采集时上报未知/需本机处理，不假报停止。
5. 引擎 hold：正常停止与异常断流都释放本会话持有键；进程强杀时不能依赖 finally，必须在测试与恢复设计中单列。
6. 软件更新/配置写入：准入与输入/音频活动使用统一互斥规则，避免检查空闲后新会话穿入。
7. App 重启：清除运行授权，保留设备/布局；不会因为持久化 shared 请求或过期租约开麦。

## 17. 验证体系、环境与执行规则

### 17.1 四层验证

- L1 单元/契约：格式、边界、状态、缓存、原子写入、队列、权限与错误语义；不能调用真实用户输入。
- L2 集成/故障注入：隔离的接收器、测试凭据、临时 data、可控网络、假引擎/真实 API，验证端到端协议与异常；模拟必须标记。
- L3 真机：实际手机/电脑、虚拟设备/输入法、系统权限、锁屏、输入焦点和升级。所有音频/键盘测试使用专用文本窗口与明确测试语料。
- L4 外部使用：非开发者按公开包/说明独立安装；记录卡点，不由维护者代操作后再统计为自助成功。

单元测试优先覆盖风险和行为，不以堆数量作为质量门槛。现有 91/14/23 是历史记录；新增失败不能通过改断言掩盖。

### 17.2 测试台账和数据隔离

准备至少两个 Windows、一个 Apple Silicon Mac、规定 Android 设备；R3 加两代 iPhone；R2 的五台真实接收设备必须同时可用。Intel/ARM64 宣称支持前提供对应真机。模拟器可以验证布局和协议，不替代麦克风、驱动、TCC、省电或系统安装器。

建立设备匿名编号、测试账号、独立配对/签名测试材料、隔离目录和焦点测试窗口。不得把测试音频发送到无关电脑、生产会话或真实聊天；不得读取或导出用户私有配置作为公开证据。任何会操作现有设备、发布、迁移或撤销真实凭据的执行任务另按实际授权处理。

### 17.3 执行顺序与失败处理

静态检查 → L1 → L2 → 专项真机 → 负载/恢复 → 更新/干净安装 → 外部试用 → 冻结候选 → 发布后下载复核。安全破坏/数据丢失立即停止相关测试，保存脱敏证据并恢复测试台。

FAIL 修复后重跑原失败用例和受影响回归；修复音频/会话/身份/更新契约时重跑全部关联四组合。BLOCKED/NOT_RUN 不允许通过改成 N/A 规避；只有该发布档位明确不含的能力才可 N/A。轻微显示问题可作为已知问题接受，需负责人、理由与修复计划。

### 17.4 性能取样

每个性能场景至少100次有效操作（长测除外），同时报告失败率、超时数、p50/p95/max、原始样本和剔除规则。冷/热、USB/LAN、各设备分开统计；不能只展示最优样本。启动失败计入成功率和超时，不能从统计中悄悄删除。

同设备用单调时钟；跨设备不能直接相减墙上时间。音频时延使用同一捕获设备/可校准回环、序列标记或同步方法，记录测量误差。第三方识别文本延迟单列。隐私允许的合成音频夹具可以保存，真实用户语音默认不落盘。

### 18.6 六个高风险用例的执行细则

**V12 撤销正在使用的手机**：A/B分别配对，A向接收端持续发送带序号合成帧；B仅读自己的状态。电脑本地撤销A，记录最后接受帧、流关闭、受控键释放与凭据拒绝时刻。A重复旧凭据、旧session、新session请求均拒绝，B仍可正常使用。建议撤销生效≤1秒（D03冻结），不能只阻断新HTTP而放过已有长流。

**V25 取消后迟到启动**：延迟start响应与音频建连，用户在100ms/500ms/接近6s时取消；取消后再放行原请求。确认旧session终止、新session可用、系统麦克风关闭，接收端不会因迟到start再按引擎键。随后开始新会话并放行旧stop，确认新会话继续。对每个受控端跑相同排列。

**V35 尾音保护**：先用具有可识别序号的合成PCM校验完整帧，再用测试者明确同意的短语料人工验证。分别记录最后一帧采集、最后上传、EOF确认、虚拟输出排空、引擎停止；停止后新采帧数必须为零，已采帧可继续传。网络故障场景允许有界丢失并报错，不允许继续采集等待网络。

**V47 两组配置冲突**：读取voice=v1/connection=c1；编辑两页；第二客户端将connection改为c2；本手机保存voice。其connection草稿与c1必须保留，再保存connection应409，不能自动用响应中的c2覆盖本地revision而消除冲突。覆盖用户远端修改前必须重新读取/比较。

**V54 发布门失败注入**：在测试发布任务中依次制造缺APK、错sequence、打包检查非零退出、报告未上传、签名失败。每种情况下不存在“可发布”候选或Release上传。开发工件上传可降级告警，但正式发布任务不得继承当前B03的continue-on-error容错。最后匿名下载验证文件哈希与验收清单相同。

**V59 更新断电恢复**：只在可恢复的隔离测试台操作。记录原版本、两个EXE哈希、data摘要；在每个事务阶段故障注入后重新启动，记录事务日志、选定版本、修复提示、配置可读性。若自动恢复尚未实现，R0可公开说明本机修复路径；R1必须证明普通用户按说明恢复且不会启动混合版本，不能把捕获异常回退当作断电已验证。
