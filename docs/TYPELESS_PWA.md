# Typeless 手机网页（当前开发路线）

2026-10-04。手机采集声音，电脑原来的 Typeless 识别并输入文字。无需下载语音模型，也无需 App Store。源码预览还未正式发布；请使用包含本次更改的 Windows `PhoneDeck.Server` 或 macOS `PhoneDeck.Receiver` 构建，不要启动 `PhoneDeck.Desktop` 的独立 Whisper 实验包来代替。

## 首次连接

1. 启动原接收端的新构建，打开 `http://127.0.0.1:8765/`。页面标题为「言渡 · 手机语音面板」，明确显示无需语音模型。
2. Mac 安装并准备 BlackHole 2ch，Typeless → 设置 → 音频 → 麦克风中选 BlackHole；设备重命名后也可能显示「PhoneDeck Mic - BlackHole 2ch」。Windows 则使用 VB-CABLE，并在 Typeless 选择 CABLE Output。确认接收端所需的辅助功能/输入权限。
3. 页面展开首次使用说明，导出**这台接收端**的公开 CA 证书，传到手机并在系统中安装信任。旧实验包与原接收端默认数据目录独立，其证书不能随意混用；不复制私钥、不跳过浏览器安全警告。
4. 点「连接手机网页」，用手机浏览器扫码，核对校验码并在电脑确认。保持电脑运行、手机网页前台。iPhone 可添加到主屏幕；安卓也可使用浏览器入口。
5. 手机主动点大话筒并授权麦克风。点击和按住模式使用电脑引擎档案的第一个已配置模式；默认 Typeless 为听写。共享模式先开手机供音，再用电脑自己的输入法快捷键开始/结束。

USB 开发验收可复用 `adb reverse tcp:8768 tcp:8768`，手机使用 `https://localhost:8768/phone/`；仍需信任证书与独立配对，不能把 USB 隧道结果当成 Wi-Fi 验收。普通使用以电脑页面提供的局域网 HTTPS 地址为准。

## 行为与兼容范围

- 保留三套完整手机 UI、方式切换、Goal（`/goal` 加回车）、退格和回车。基础键只向已确认目标发送，输入测试应使用专门文本框。
- 普通语音跟随电脑的可靠停止状态结束手机采音。未知或过期探针不当作停止；开始确认前的缓存不能停掉新语音。Windows 停止延迟还受原后台探针刷新周期影响，需在实机测量。
- 点停止后手机立即关麦，页面可短暂显示收尾，等待电脑播放完最后一段音频并确认输入法停止。异常等待上限为 16 秒；失败会明确提示收尾未确认，恢复连接后可以重新开始，不能把失败提示当成文字已完整提交。
- 共享时各电脑独立开始和停止 Typeless，手机继续给共享组供音。**先在电脑结束本段，再关闭手机供音**。PhoneDeck 不保证取消或撤回第三方输入法的文字。
- Mac 和 Windows 可作为主电脑。附加电脑沿用一次性配对 JSON、目标 ID、逐设备 Bearer 和证书固定；现有 Windows 安全扫码接收端可接入。旧 Mac 接收端尚无该附加电脑配对契约，本轮没有用永久共享密钥绕过它。内置 Desktop 实验 peer 保留兼容，但不是本路线的必需项。
- PWA 前台使用。离开页面、锁屏、断线会关闭采音，重连不自动开麦。不承诺锁屏后台共享或所有 iPhone / 安卓机型已通过。
- 拓展输入法使用已有 `voice-engines/*.json` 和平台引擎档案，不把本机快捷键写死在 UI。拥有不可靠采集探针的引擎只能按实际能力验证，不能仅改名称就宣布支持 managed 控制。

## 开发入口

- 共用页面：`desktop/PhoneDeck.Desktop/PhoneWeb`。
- 共用嵌入清单和原接收端宿主：`shared/PhoneWeb`。
- 会话/传输接口：`IWebPhoneTarget`，本机目标通过工厂注入；原接收端使用固定回环 API，实验 Desktop 的内置识别 target 独立保留。
- Windows / Mac 的原构建入口会嵌入网页与 QRCoder；不需要 `scripts/build-desktop.ps1` 的 Whisper 构建步骤。模型代码没有链接进这两个原接收端。

自动化结果和当前真机待办见 [HANDOFF](HANDOFF.md)。证书安装、手机实际录音、Typeless 转写和多人/多电脑同时使用必须单独验收。
