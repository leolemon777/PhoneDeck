# 手机统一设置与精简桌面

开发线：Windows 1.6.0-dev.16 / sequence 28，Android 1.6.0-dev.21 / versionCode 27。

## 使用与配置归属

- 手机「设置 → 电脑与输入法」或首页电脑列表的「电脑设置」：选择一台已配对电脑，读取输入法、模式快捷键和连接设置。
- 手机保存输入法选择、键位覆盖、USB 自动恢复、LAN 发现或登录启动后，Windows 即时应用，不重启音频服务。
- 输入法和连接设置属于对应电脑；布局、Agent 按键、主题、点击/按住与共享工作方式属于手机。切换电脑不再自动覆盖手机布局。
- 快捷键留空沿用引擎读取值/默认值；自定义键位须与第三方输入法自身设置匹配。实验档案仍标注待验证。
- 共享麦克风无需选择受控引擎。新版手机不再跟随旧电脑的 `shared.requested` 自动录音，用户从手机主动开启/停止。
- 输入法安装、登录、虚拟声卡及系统权限仍由电脑首次完成；不通过手机远程执行任意安装器或命令。
- 手机可导入签名更新 ZIP，验证后再发起已有的逐台更新流程。也兼容电脑缓存的签名包。

Windows 原生托盘仅保留状态、重连、退出。窗口按需创建，关闭后销毁；最小化暂停 UI 定时器。
登录启动写入固定安装路径和 `--tray`。数据目录保留原控制台规则：显式 `PHONEDECK_DATA_DIR`，否则程序旁 `data`。
接收端仍独立运行，USB 恢复、健康诊断、音频队列和尾音规则保持原基线；没有强制 GC 或挤出工作集。

## 配置协议

可选能力 `phoneManagedSettingsV1`，输入协议仍为 v2。

| 路径 | 用途 |
|---|---|
| `GET /api/config/desktop` | 身份、busy、引擎档案、覆盖值、连接设置、两组 revision |
| `POST /api/config/desktop/voice` | `targetComputerId`、`revision`、`activeEngine`、`shortcutOverrides` |
| `POST /api/config/desktop/connection` | `targetComputerId`、`revision`、可选 `usbWatchdog` / `lanDiscovery` / `autoStart` |

LAN 沿用 HTTPS、token、证书固定。手机 USB 回退先检查 health 身份；读取和保存响应再次核对 computerId。
写入不自动重试或切换目标。超时提示重新读取，避免把未确认保存当作成功。
revision 是对应设置的 SHA-256；错目标/无效键位返回 400，忙碌/过期返回 409，落盘失败返回 500。
配置写入与输入/音频请求互斥，活动流直到尾音处理结束才释放使用许可；另检查受控会话和引擎采集状态。
新配置原子落盘后替换内存中的引擎集合。连接保存保留既有 adbPath 和共享请求字段，不允许远程指定可执行路径。
旧引擎 GET 继续可读，旧无目标/版本校验的引擎 POST 返回 409 并指向手机入口。
旧 Mac/Windows 缺少能力时手机提示升级；不宣称 Mac 或 iOS 已实现这套配置。

## 验证事实与限制

- Windows：91 项测试通过，包括新增目标/版本校验、忙碌互斥、写入异常恢复、绑定白名单与原子替换失败保护。
- Android：Debug/Preview 构建、14 项单测、lint 通过；lint 仍有 44 项 warning、0 error。
- 本机 Windows 经发布者签名包更新成功，版本/序号/电脑身份及产物哈希核验；当前输入法已恢复原值。
- 原手机备份的证书指纹和配对密钥可访问新版 HTTPS 配置接口；不带 token 返回 401，身份未改变。
- 实际 API 测试：错误目标、旧 revision、未知引擎、非法键位均拒绝；切到微信输入法档案后 health 更新，再切回 Typeless，接收端未重启。
- 新原生窗口的隔离探针验证托盘启动无窗口、连续 10 次打开/关闭后释放 Form，以及便携数据目录默认值。
- 一次 40 请求的本机 health 采样：中位数 0.49 ms，最大 24.05 ms。这是本地 HTTP 读延迟，不是录音或听写延迟。
- 更新前正在运行的旧界面私有提交约 185.7 MiB、工作集 186.3 MiB；新托盘私有提交约 13–14 MiB、工作集约 56–57 MiB。
  新接收服务另占私有提交约 27–29 MiB、工作集约 86 MiB。长时旧进程与新进程预热不同，这些是现场观测，不能当作严格同负载基准或所有机器保证。
- 自包含界面 EXE 仍约 154 MiB（Windows Desktop 运行时仍随包附带）；本轮收益主要是常驻内存与界面复杂度，未对共享运行时做脆弱裁剪。
